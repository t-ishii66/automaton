# 01. オートマトンとは

非決定性有限オートマトン (NFA) から決定性有限オートマトン (DFA) への変換は、
正規表現やコンパイラの字句解析に使われる基礎技術であり、実装も容易である。

この章では、そもそもオートマトンとは何か、DFA と NFA は何が違うのかを、
以降の章でずっと使う例

```
a(a|b)*bb
```

で確認する。

## 有限オートマトン

有限オートマトンは、**状態**と**遷移**だけでできた機械である。
入力を 1 文字ずつ読み、読んだ文字に応じて今いる状態から次の状態へ移る。
入力を読み終えたときに最終状態にいれば「受理」、そうでなければ「不受理」。

図の読み方は次の通り。

| 表記 | 意味 |
| --- | --- |
| 丸 | 状態 |
| 左から矢印が入っている丸 | 初期状態 |
| 二重丸 | 最終状態（受理状態） |
| 矢印と、その脇の記号 | その記号を読んだときの遷移 |
| オレンジの矢印（`ε`） | 入力を読まずに遷移できる（ε 遷移） |

## 決定性有限オートマトン (DFA)

DFA は次の 2 つを満たす有限オートマトンである。

1. ε による遷移がない
2. 1 つの状態から同じ記号による異なった状態への遷移はない

この 2 条件は、**「今の状態と次の 1 文字が決まれば、次の状態がただ 1 つに決まる」** と言い換えられる。
迷う余地がないので、プログラムは入力を先頭から 1 回なぞるだけでよい。後戻りも探索も要らない。

## 非決定性有限オートマトン (NFA)

上の 2 条件を満たさないものが NFA である。
正規表現 `a(a|b)*bb` から素直に作ると、次のような NFA になる。

![正規表現 a(a|b)*bb に対応する NFA](img/01-nfa.svg)

オレンジが ε 遷移である。状態 `1` からは ε 遷移が 2 本出ていて、
`2` へ行くか `4` へ行くかが入力では決まらない。
これが「非決定性」である。このままでは、どちらを選ぶかを試しながら進む（＝後戻りする）
プログラムを書くしかない。

ここまでで、例と、DFA・NFA の区別が出揃った。
あとは「この NFA をどうやって作るのか」と「これをどうやって DFA に直すのか」である。
